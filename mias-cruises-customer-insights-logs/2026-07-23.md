# Mia's Cruises Customer Insights Log - 2026-07-23

## 项目背景

Mia's Cruises Customer Intelligence Platform 这条线已经完成了 validation harness、internal review console、React 路由切分和多轮 Mia chat 改造。今天的重点不再是大功能，而是把 MIA 的对话逻辑调得更像正常商业聊天，同时让默认回答更适合用户直接阅读。

## 当天目标

1. 让 MIA 正确识别 `OK`、`i got it`、`thanks`、`MIA` 这类确认句，并把它们当成 small talk / thanks，而不是 report 问题。
2. 让默认聊天回答只给用户看结果，不再显示 `Short answer:`、`Evidence used:`、`Evidence shown in this answer` 之类后台标签。
3. 让中文和其他支持语言按用户输入自动回复，不要硬编码成 English。
4. 让聊天窗口更像成熟产品：可展开、Enter 直接发送、思考提示更自然、`Manager` 改成 `You`。

## 行动总结

- 调整了 backend intent routing，让 acknowledgements、thanks 和轻量唤醒词优先走 small talk。
- 改写了默认回答格式，去掉用户可见的证据标签，只有用户明确要求证据时才展开 supporting evidence。
- 前端聊天窗口改为自动识别输入语言，并把语言传给 `/api/chat`。
- 增加了 expandable chat drawer、Enter-to-send、友好的 thinking 文案，以及更自然的消息标签。
- 普通问答现在默认不渲染证据卡片；只有用户明确问 evidence / sources / 佐证 时才展开。
- 针对 live answer 仍返回 `Short answer:` / `Evidence used:` 的情况，新增后端和前端双层 answer sanitizer：普通问题会在显示前强制移除这些标签和证据段。
- 为这次语义修正新增了单元测试，锁住 small talk、中文感谢句和无证据默认回答的行为。

## 实现内容

- `server.py`
  - 扩展 `classify_conversation_intent()`，让 `OK, i got it, thanks, MIA`、`好的，谢谢 Mia` 这类句子进入 `thanks` 语义。
  - 调整 `build_messages()`，默认答案不再要求输出 `Short answer` / `Evidence used` 的可见结构。
  - 调整 `evidence_only_answer()`，默认只给结果和主要信号，只有明确问证据时才展开 supporting evidence。
- `app/components/chat-widget.jsx`
  - 引入 `detectInputLanguage()`，按用户输入语言发送 chat 请求。
  - 加入 `expanded` 状态，支持扩大聊天窗。
  - 输入框按 `Enter` 直接发送，`Shift+Enter` 保留换行。
  - 消息标签从 `Manager` 改成 `You`，加载态文案改成更自然的本地化提示。
  - 默认不再渲染证据卡片。
- `app/styles.css`
  - 新增 expanded chat drawer 的尺寸规则和 header action 样式。
  - 让聊天窗在桌面和移动端都能正常伸缩。
- `app/scripts/features/chat-assistant.mjs`
  - 同步旧 fallback 路由的 small talk / thanks 语义，避免入口切换时行为不一致。
- `work/test_mia_response_structure.py`
  - 新增 acknowledgement / small-talk 语义测试。
  - 新增默认回答不暴露内部标签的测试。
