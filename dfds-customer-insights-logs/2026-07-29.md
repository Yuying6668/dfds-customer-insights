## IT Data Flow 与 Mia Chat 上下文
- 修复 IT Data Flow 上传批次只向 Mia 提供文件概要的问题。
- Mia 现在会接收当前登录用户上传批次的脱敏字段分布，以及清洗统计：接收行数、清洗后行数、移除空行、移除重复行和标准化的缺失值数量。
- email、客户编号、loyalty number、账户或设备 hash 等受限字段仍不会进入 Chatbot 上下文。
- 因此用户可在上传后询问原始数据和清洗后数据的规模、字段分布、路线/评分/日期等非敏感值的标准化情况，以及清洗处理结果。

## IT Data Flow 六阶段清洗可见性
- `Cleaned uploaded data` 卡片现在展示上传批次的真实清洗结果：接收与保留行数、移除空行、移除重复行、标准化缺失值、映射业务值和待复核映射例外。
- 六阶段状态由后端上传批次驱动：Upload、Validate、Classify、Map、Review、Ready for Mia；保存清洗数据后，Review 与 Ready for Mia 会完成。
- 清洗规则会统一字段名、修剪文本、规范空值和哨兵值、剔除空行与精确重复行，并标准化已知航线、日期、金额和评分。原始文件只读保留，清洗结果可另存或导出。
- 补充航线别名映射，`Newcastle-IJmuiden` 等已知标准航线不会再被错误计为 `Unmapped`。

## IT Data Flow 标准化与自检强化
- 日期字段现统一为 `dd/mm/yy`，包括 ISO 时间戳与带时间的历史格式；例如 `2026-07-21T12:00Z` 会显示为 `21/07/26`。
- 同步规范营销同意值、iOS/Android 平台名称和旧品牌渠道；清洗后的展示使用 `Mia's Cruises App`，原始上传文件保持不改写。
- 新增前端 `Data quality self-check`：显示无效日期、金额、评分、未映射航线、枚举例外、缺失/重复标识、混合年龄格式和模糊引用字段的实际计数。
- 有未解决映射例外时，即使保存了清洗导出文件，`Review` 仍为 `needs_review`，`Ready for Mia` 保持 `pending`；不得将六阶段错误标为全部完成。

## UTC ISO-8601 日期标准
- 按更新后的企业数据 PRD，前端预览和清洗输出统一使用 UTC ISO-8601：`YYYY-MM-DDTHH:mm:ssZ`，不再使用 `dd/mm/yy`。
- 支持 ISO 时间戳、带时区时间、日/月/年、月-日-年、点分日期和英文月份日期；带时区值换算到 UTC，无时区值按 UTC 解释。
- 当前处理范围覆盖 travel、departure、payment、event、published、source received、consent timestamp 和通用 created/updated 时间字段；原始文件格式仍完整保留。

## 缺失值 NULL 合同
- 更新数据合同：所有缺失值统一为真正的 `NULL`，包括空白、`N/A`、`-`、`Unknown`、`null` 和 `None`；不再对分类字段使用字符串 `Unknown` 作为占位。
- API 清洗预览输出 JSON `null`，前端将其显示为 `Not provided`，Excel 导出保持空单元格；Mia 的上传数据上下文会跳过 `null`，不会把它识别为文本值。
