# 2026-08-11

## 项目背景

Mia's Cruises Customer Intelligence 项目当前以三张独立 LangGraph 为 agentic workflow 边界：Conversation Graph 负责证据问答，Dataset Insight Graph 负责内部批次洞察与建议草稿，Evaluation Graph 负责冻结集评估、分段指标和 promotion gate。本次工作以 `docs/superpowers/specs/2026-08-09-mia-agentic-customer-intelligence-design.md` 为验收基线，重点核查此前暴露的闭环缺口。

## 当天目标

- 让三张图在本机可重复执行，并保留统一 trace、graph version、idempotency key 和 checkpoint 合约。
- 将节点级 bounded retry、failure state、last safe state 覆盖到三张图的实际路径。
- 接入外部刷新和模型/prompt/retriever 版本变更的受治理触发入口。
- 让人审校准结果进入整体指标、分段指标和 promotion gate。
- 防止原始上传字段、身份字段和 Evaluation held-out labels 进入 graph checkpoint。
- 按设计文档记录可验证完成项与仍受外部环境限制的项目。

## 行动总结

- 重新核查 Conversation、Dataset、Evaluation、server 入口、demo、checkpoint 和治理 preflight。
- 新增/完善共享 retry recovery contract：每个节点最多 3 次尝试，失败时写入 `failure_state`、失败节点、错误摘要、`retry` 和 `last_safe_state`，并进入图内恢复路径。
- 新增外部 refresh 与组件版本变更的 trigger adapter，并通过 server 的受治理事件入口分派 Dataset 或 frozen Evaluation。
- 将 Evaluation 的 held-out label 准备移到 graph 外部 `label_vault`；production graph state 只接收 live case，score 节点仅在内存中关联标签并写回聚合结果。
- 在 Dataset graph 入口复用受限字段检查，拒绝 `rows`、原始上传、email/phone/address、credentials 等内容。
- 更新 demo 使用真实编译 graph、memory checkpointer、三图共享 trace 和各图 trace records。

## 实现内容

- `backend/mia_graph/retry.py`：统一 bounded retry 和 safe-state recovery。
- `backend/mia_graph/conversation.py`：Conversation 节点、review queue 和失败终止路径纳入 recovery；state 补充 graph version/idempotency/failure 字段。
- `backend/mia_graph/dataset.py`：Dataset 所有节点纳入 recovery；执行前校验 aggregate snapshot，失败结果保留 safe state。
- `backend/mia_graph/evaluation.py`：Evaluation 节点 recovery；label vault 隔离 held-out labels；human-review metrics 写入整体与 language/route/source-type 分段。
- `backend/mia_graph/triggers.py`：外部刷新和组件版本变更事件适配器及 scheduler facade。
- `backend/mia_graph/contracts.py`：新增 Dataset snapshot restricted-input validation。
- `server.py`：新增 `/api/admin/mia-triggers/external-refresh` 和 `/api/admin/mia-triggers/version-change` 入口；生产 Conversation 传入稳定 idempotency key；Evaluation 生产运行在 checkpoint graph 外准备 label vault。
- `scripts/run_mia_demo.py`：串行执行 Dataset → Conversation → Evaluation，并输出共享 trace records。
- 测试新增 trigger wiring、raw snapshot rejection、answer/judge failure recovery、human segment metrics、demo trace linkage 等回归覆盖。

- `.venv/bin/python -m unittest discover -s tests -p 'test*.py'`：85 tests passed。
- `scripts/run_mia_demo.py`：生成一个 published internal batch、external evidence、cited answer、insight draft、conditional review 和 evaluation report。
- demo 验证：三图顺序固定为 Dataset、Conversation、Evaluation；三图共享同一个 trace ID；trace records 含 graph version、prompt version、retrieval version、validation verdict 和 final outcome。
- `git diff --check`：通过。
- Dataset raw-field rejection：测试确认含 `rows`/restricted fields 的 snapshot 在 graph checkpoint 前失败。
- Production preflight 当前仍为 blocked；不是代码测试失败，而是本机缺少 OIDC、KMS、TLS/audit evidence、DPIA、processor DPA、training 等部署证明。
- `scripts/langgraph_runtime_check.py` 当前无法完成 PostgreSQL checkpoint 实测：本机 `127.0.0.1:5432` 不可连接。demo 使用 memory checkpointer 仅证明本机 graph contract，不替代 PostgreSQL 验收。
- Langfuse 在未配置 provider credentials 时保持 no-op；demo trace records 是本地 redacted contract evidence，不宣称已发送到真实 Langfuse。

## 后续注意点

- 外部数据 refresh worker 仍需在部署环境中向 trigger 入口投递已批准的 completed event；当前仓库提供事件处理路径，但不凭空创建外部 scheduler 或 cron。
- 版本触发器的去重 facade 当前为进程内状态；生产部署应将 component/version marker 持久化到数据库或队列幂等表，避免进程重启后重复 evaluation。
- PostgreSQL checkpoint、真实 Langfuse trace、OIDC/MFA/KMS/TLS/audit、processor residency/DPA、DPIA 和 operator training 必须在目标环境分别完成证据验收。
- `docs/superpowers/specs/2026-08-09-mia-agentic-customer-intelligence-design.md` 仍是设计基线；任何新增个人数据、权利影响决策、外部处理器或 high-risk 用例都要重新经过 Legal/DPO 和 production governance gate。
